Why this exists

Railway's feel. Your server. Your rules.

Hosted platforms are great until the bill, the lock-in or the data question shows up. Self-hosted ones are great until you spend a weekend on them. This tries to be the short path between the two.

Fastest start

One command

Install on a bare VPS or from your laptop over SSH. Docker, HTTPS and the panel are set up for you, and nothing you already run is touched.

Lightest

~65 MB

One Go binary and one SQLite file, plus Caddy. Measured on a real 16 GB VM next to other services, not on a clean demo box.

Most careful

Locked down

Two-factor, passkeys, an audit log, encrypted secrets, read-only API tokens. The installer never switches a firewall on for you.

Yours

No lock-in

Apache-2.0, no accounts, no telemetry. Logs stay on your machines, and AI analysis can run on your own computer.

Install

From empty server to live app in minutes.

$ curl -fsSL https://raw.githubusercontent.com/KumarRoushan9234/OSS-Railway/main/install.sh | sh

Ubuntu, Debian, RHEL, Fedora, Rocky or Alma · x86-64 or ARM64 · 1 GB RAM minimum · ports 80 and 443 open.

Run the command

It installs Docker if missing and starts the panel and Caddy. Existing containers and firewall rules are left alone.

Open the address

You get a real HTTPS address like https://203-0-113-7.sslip.io right away. No DNS needed.

Claim it with the setup code

The one-time code in the output creates your admin account. Then turn on two-factor.

Deploy something

Connect GitHub, paste an image, or add a database. Press N anywhere.

    Questions
    Asked a lot.
    
    
    
      
    Is it free?
    Yes. Apache-2.0, no accounts, no telemetry. You pay only for your own server.
    
      
    Is it ready for production?
    Not yet. It's an alpha: tested on my machine and a real VM, but it hasn't had months of use. Don't put anything critical on it.
    
      
    What can the panel do to my server?
    It controls Docker through the Docker socket, which is the same as root. Treat the dashboard like an SSH login: strong password, two-factor or a passkey, HTTPS. It only manages containers it created (named ossr-…) and lists the rest read-only.
    
      
    Will it break what I already run on the server?
    It's built not to. The installer leaves the firewall alone unless one is already on, and only adds its own containers on ports 80 and 443. I ran it beside live services on a 16 GB VM and they kept answering.
    
      
    How is it different from Coolify or Dokploy?
    Those have far more features and years of real use. This is a smaller, newer take: one Go binary, about 65 MB of RAM, Railpack builds, and a canvas-style dashboard. Pick those if you need maturity today.
    
      
    Do I need a Dockerfile?
    No. Without one, Railpack detects your language and builds the app. If the repo has a Dockerfile, that is used instead.
    
      
    My server has no public IP.
    Turn on Settings → Remote access to reach the dashboard through a Cloudflare Tunnel, with no open ports.
    
      
    Does any of my data leave the server?
    No telemetry. AI log analysis only sends logs to the endpoint you choose. Point it at Ollama and it stays on your own machines.
