Everything a small team needs to ship.

No Dockerfile, no CI pipeline, no reverse-proxy config. The dashboard does it.

Push to deploy, no Dockerfile

Connect GitHub once and pick a repo. Railpack detects Node, Python, Go, PHP, Ruby, Java, Rust, .NET and more, and builds it. Every push to your branch deploys again.

Databases you link by dragging

Postgres, MySQL, Redis and MongoDB in one click, with daily backups. Drag a line from a database to an app and it gets ${{db.DATABASE_URL}}.

HTTPS without touching DNS

Caddy gets certificates automatically. Every app gets a free name.your-ip.sslip.io address on day one; add your own domain whenever you like.

Know when something breaks

Live logs, CPU, memory, network and disk per service. Email, Slack or Discord alerts for crashes, out-of-memory kills, failed deploys and full disks, plus a daily report.

See everything on the server

The Server view lists every listening port with the process and container behind it, every container (even ones you started by hand), volumes and disk use. Give each app a CPU and memory limit, or take the suggestion sized from its real usage.

Locked down, agent-ready

Two-factor sign-in with any authenticator app, one-time recovery codes, and an emailed sign-in link if you lose your phone. API tokens and an MCP endpoint let Claude and other AI agents read logs, check status and deploy.

Desktop app for every server

Add any number of servers, a VPS anywhere or a box at home behind a tunnel, and watch them from one window. Tokens stay in your system keychain, and log analysis runs on your own computer with Ollama.

Logs you can search, explained

Every service's logs are kept for 7 days and searchable across services. One click asks an AI model why a deploy failed: a local Ollama by default, so your logs stay yours.

From empty server to live app.

Install

Run one command on an Ubuntu, Debian or RHEL-family server. It installs Docker if needed, opens the firewall and starts the panel and Caddy.

Sign in

Open the printed address, enter the one-time setup code and create your admin account.

Deploy

Pick a GitHub repo, a Docker image or a database. A health-checked deploy goes live, and the old version keeps serving until the new one is ready.

Requirements

  • A Linux server: Ubuntu, Debian, RHEL, CentOS, Fedora, Rocky or AlmaLinux, on x86-64 or ARM64
  • 1 GB RAM minimum, 2 GB or more for building apps (the installer adds swap on small servers)
  • Ports 80 and 443 open to the internet, and root or sudo access

Install

On the server:

curl -fsSL https://raw.githubusercontent.com/KumarRoushan9234/OSS-Railway/main/install.sh | sh

Or from your own computer, over SSH:

npx oss-railway setup root@YOUR_SERVER_IP

The installer prints a dashboard address like https://203-0-113-7.sslip.io and a one-time setup code. Open the address, enter the code and create your account.

First deploy

  1. Press New (or N). Type to search: a repo name, an image like nginx:alpine, or a database.
  2. For GitHub, choose Connect GitHub. This creates a private GitHub App on your account that only sees the repos you pick.
  3. Add variables if your app needs them, then Save and deploy. Build logs stream live.
  4. When it's live, the card turns green and shows its address.

Without a Dockerfile, Railpack builds the app. If the repo has a Dockerfile, that is used instead. Apps should listen on the PORT variable (3000 unless you set another port).

Domains and HTTPS

Every app starts with a free name.IP.sslip.io address. To use your own domain, point DNS at the server, then set it in the service's Settings tab:

A    app.example.com   →  YOUR_SERVER_IP
A    *.example.com     →  YOUR_SERVER_IP   (optional, for name.example.com on every app)

Caddy requests and renews certificates on its own.

Alerts and reports

In Settings, add an SMTP server (any provider: Resend, Postmark, SES, Gmail) and/or a Slack or Discord webhook. You'll hear about crashes, crash loops, out-of-memory kills, failed deploys, failed backups, disk above 85% and memory above 90%. The same alert is sent at most once every 15 minutes. A daily summary goes out at 09:00 server time.

Server view and limits

Open Server in the top bar to see every listening port (with its process and container), every container on the machine (deployed here, or external), volumes and disk use.

In a service's Settings → Resources, set a CPU limit (cores) and a memory limit (MB). Changes apply to the running container straight away. After a few minutes of data you get a suggestion: 1.5× the measured peak, with a warning when a service keeps hitting its limit. Docker can't cap disk per container, so disk use is shown and alerted on instead.

Two-factor sign-in

  1. Settings → Two-factor sign-in → Set up authenticator app. Scan the QR code with Google Authenticator, 1Password, Authy or any TOTP app.
  2. Enter the 6-digit code to turn it on, then save the 10 recovery codes. Each works once.
  3. Lost your phone? After your password, use a recovery code, or choose Email me a sign-in link (needs email set up). The link works once for 15 minutes and turns 2FA off so you can set it up on the new phone.

Passkeys (Settings → Passkeys) sign you in with Windows Hello, Touch ID, a phone or a security key, with no password or code. They need HTTPS and a domain name. Settings also has change password, sign out everywhere else, and an Activity log of every sign-in and change.

AI agents (MCP)

Create a token in Settings → API tokens and AI agents. Read-only tokens can list services, read logs and see the server; full tokens can also deploy and restart. Then add the server to Claude Code:

claude mcp add --transport http oss-railway https://YOUR_PANEL/api/mcp --header "Authorization: Bearer ossr_…"

Tools: list_services, service_status, service_logs, deployment_logs, server_overview, deploy, restart. The same token works on the REST API with Authorization: Bearer. Tokens can never change settings, tokens or 2FA.

Logs and AI analysis

Each service's Logs tab has Live and Search. Search covers the last 7 days; every word you type must appear. Lines are kept in SQLite on your server.

Settings → AI analysis takes any OpenAI-compatible endpoint. With Ollama on the server or your computer (http://host.docker.internal:11434/v1, model e.g. qwen2.5:7b), nothing leaves your machines. Then use Explain with AI on a failed deploy or in Logs.

Remote access

No public IP, or don't want to open ports? Settings → Remote access:

  • Get a temporary address: a random https://….trycloudflare.com link, no account needed. Good for testing; it changes on restart.
  • Use my Cloudflare tunnel: create a tunnel in Cloudflare Zero Trust, point a hostname at http://ossr-caddy:80, paste the token. A fixed address on your own domain.

Anyone can open a tunnel address, so turn on 2FA or a passkey first. GitHub push-to-deploy works through a tunnel.

Desktop app

Download the installer for Windows, macOS or Linux from the latest release. Add a server with its dashboard address and an API token (read-only to watch, full access to deploy and restart). The app shows each server's CPU, memory, disk, services, alerts and ports; reads and searches logs; deploys and restarts; and opens the full dashboard in its own window.

Analyze sends a service's recent logs to Ollama on your computer (set the model under AI settings), so a remote server's logs are analysed at home.

Updates and releases

Every change merged to main is released automatically: a new version tag, release notes, Linux binaries and a panel image at ghcr.io/kumarroushan9234/oss-railway. To update a server, run the install command again. Your data stays in the ossr-data volume.

Run it locally

With Docker Desktop running:

docker build -t oss-railway:dev .
docker network create ossr
docker run -d --name ossr-panel --network ossr \
  -v /var/run/docker.sock:/var/run/docker.sock -v ossr-data:/data \
  -v /proc:/host/proc:ro -v /:/host/root:ro --cap-add SYS_PTRACE --add-host host.docker.internal:host-gateway oss-railway:dev
docker exec ossr-panel cat /data/setup-code

Open http://localhost. To work on the dashboard with instant reload, run npm run dev in web/ and open http://localhost:5176.

Security

  • The panel controls Docker on the server, which is the same as root access. Use a strong password and keep the dashboard on HTTPS.
  • Variables, SMTP passwords and GitHub keys are encrypted at rest. Secrets are never shown again after saving.
  • Sign-in is rate-limited, sessions are HTTP-only cookies, and every change needs a CSRF header.
  • Found a problem? Open a private security advisory on GitHub rather than a public issue.
